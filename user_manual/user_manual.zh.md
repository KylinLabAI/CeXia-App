## 1. CeXia 是什么

CeXia（策匣）运行你的**虚拟一人公司**。你 — 创始人 — 创建任务、设定优先级。一支由 AI 驱动的 Agent 团队 7×24 小时执行这些任务。

**你的角色**：查看看板、创建工作、批准新 Agent、做出战略决策。

**Agent 的角色**：认领任务、执行任务、汇报结果。无需微观管理。

### 9 个 Agent 角色

| 角色 | 为你做什么 |
|------|-----------|
| **产品经理** | 撰写 PRD、管理待办列表、定义验收标准 |
| **架构工程师** | 设计系统架构、选择技术栈 |
| **全栈工程师** | 实现功能、修复 Bug — 可并行运行多个副本 |
| **UI/UX 设计师** | 创建设计、线框图、产品文案 |
| **QA 工程师** | 运行测试、报告 Bug、验证发布 |
| **运维工程师** | 监控系统、分析数据、运行流水线 |
| **市场营销** | 创作内容、管理活动、驱动增长 |
| **行政与财务** | 生成报告、追踪成本、监控系统健康 |
| **巡检哨兵** | 清理过期锁、审计操作、从故障中恢复 |

### 30 秒快速理解

```
1. 你在 WebUI 中创建任务                  → 任务出现在 Backlog
2. 空闲的 Agent 认领任务                   → 状态变为 Claimed
3. Agent 开始工作（编码/设计/测试）          → 经历多个状态流转
4. 结果出现在看板上                        → Released（完成）或 Bug Open（需修复）
5. 你随时查看                             → 所有操作有日志记录，不会丢失
```

## 2. 快速开始

### 2.1 你需要什么

- 一台运行控制中心的机器（Linux、macOS 或 Windows）
- 已安装 Docker（推荐）— 或 Python 3.10+ 直接部署
- 现代浏览器（Chrome、Firefox、Edge、Safari）

### 2.2 启动控制中心

**方式 A — Docker（推荐，一键启动）**

拉取并运行官方 Docker 镜像：

```bash
docker pull crpi-5w5kegfxurclu2lz.cn-hangzhou.personal.cr.aliyuncs.com/kylinlab2026/cexia-control-center:latest

docker run -d \
  --name cexia-control-center \
  -p 8080:8080 \
  -p 8000:8000 \
  -v ~/cexia-data:/app/data \
  -e JWT_SECRET_KEY=your-random-secret-key \
  crpi-5w5kegfxurclu2lz.cn-hangzhou.personal.cr.aliyuncs.com/kylinlab2026/cexia-control-center:latest
```

控制中心运行在 **http://localhost:8080**（WebUI）和 **http://localhost:8000**（API）。在浏览器中打开 WebUI。

你的数据（任务、Agent 日志、设置）持久化存储在 `~/cexia-data` 中 — 重启和升级不会丢失。

### 2.3 首次登录

1. 在浏览器中打开 **http://localhost:8080**
2. 使用默认凭据登录：
   - **用户名**：`admin`
   - **密码**：`cexia123`
3. **系统会立即要求你修改密码** — 这是安全要求。控制中心在设置新密码之前不会正常运行。
4. 修改密码后，系统完成初始化，你将看到**仪表盘**。可以开始使用了。

### 2.4 实例管理者登录（CLI/GUI）

通过 CLI 或 GUI 管理工作实例，需要实例管理者账户：

1. 默认管理者凭据：
   - **用户名**：`manager`
   - **密码**：`manager123`
2. 通过 CLI 登录：`cexia-instance login`
3. 或通过 GUI 登录：App 标签页 → 登录表单
4. **立即修改默认密码** — 管理员应为生产环境创建专用管理者账户

### 2.5 连接你的第一个 Agent

Agent 是运行在你机器上的工作实例。你的团队设置它们并向控制中心注册。注册后：

1. 在侧边栏中进入**实例管理**
2. 找到新实例（标记为 **PENDING**）
3. 点击**批准** — Agent 现在可以认领任务

对每个 Agent 重复此过程。你可以运行同一角色的多个副本（例如，两个全栈工程师）以获得更高吞吐量。

**实例注册流程：**
1. 实例管理者通过 CLI/GUI 登录
2. 管理者注册工作实例：`cexia-instance register --name Jack --role agent-fullstack`
3. 实例获得访问令牌（`cxt_...`）并发送注册请求
4. 管理员在 WebUI 中批准 → 实例即可认领任务

## 3. WebUI 导览

### 3.1 仪表盘

仪表盘提供即时健康检查：

- **总任务数** — 系统中的所有任务
- **在线实例** — 当前活跃并连接的 Agent
- **本周完成** — 最近 7 天完成的任务
- **今日过期锁** — 超时的任务（Agent 可能崩溃）

统计卡片下方：**按状态分类的任务**（进度条）和**按角色分类的任务**（表格）。用这些来发现瓶颈 — 例如，Testing 中任务太多，但 QA Agent 在线数不足。

### 3.2 任务看板

这是你管理工作的地方。任务以**看板**形式组织，每个状态对应一列：

`Backlog → Claimed → Req. Confirmed → In Development → In Testing → Bug Open → Released`

**创建任务：**

1. 点击右上角 **+ 创建任务**
2. 填写表单：
   - **标题** — 单行摘要（必填）
   - **描述** — 详情、验收标准、链接
   - **Agent 角色** — 指定谁处理（留空表示任意角色）
   - **优先级** — Urgent / High / Medium / Low
   - **严重程度** — Critical / Major / Minor / Trivial
3. 点击**创建**

任务卡片出现在 Backlog 列中。匹配角色的 Agent 会自动认领。

**查看任务：** 点击任意卡片。侧面板打开显示所有详细信息 — 状态、分配的 Agent、优先级、完整描述。

### 3.3 审计日志

每个 Agent 的每个操作都有记录。进入**审计日志**查看：

- 哪个 Agent 做了什么
- 何时发生
- 什么发生了变化（状态转换、错误）

你可以按 Agent 名称、操作类型或时间段筛选。用于调查问题或审查 Agent 活动。

## 4. 管理你的 Agent 团队

### 4.1 实例管理页面

进入**实例管理**查看所有已注册的 Agent：

| 列 | 含义 |
|----|------|
| **名称** | Agent 的名称（如 "Jack"） |
| **角色** | Agent 做什么（如 全栈工程师） |
| **状态** | 绿色 = 在线工作中。灰色 = 离线或断连 |
| **已批准** | 绿色 = 已激活。黄色 = 等待你的批准 |

### 4.2 批准新 Agent

当你的团队注册新 Agent 时：

1. 它出现在表格中，状态为 **PENDING**
2. 点击**批准**激活它
3. Agent 现在可以认领任务

### 4.3 吊销访问权限

如果某个 Agent 需要停止工作：

1. 在表格中找到它
2. 点击**吊销**
3. Agent 立即失去访问权限 — 下次请求将被拒绝

之后可以重新注册。

### 4.4 水平扩展

需要更多开发吞吐量？让你的团队在另一台机器上注册另一个全栈工程师 Agent。在 WebUI 中批准。两个 Agent 将并行工作，各自认领不同的任务 — 无冲突、无重复。

## 5. 任务生命周期

### 5.1 任务如何流转

```
Backlog               ← 你在这里创建任务
   ↓  (Agent 认领)
Claimed               ← Agent 现在拥有该任务
   ↓  (Agent 确认规格)
Requirements Confirmed
   ↓  (Agent 开始构建)
In Development
   ↓  (Agent 完成，移交给 QA)
In Testing
   ↓  ↙
   ↓   测试失败 → Bug Open → 回到 In Development（修复）
   ↓
Released              ← 完成！任务结束
```

### 5.2 你需要知道的

- **你不需要手动移动任务** — Agent 自动处理状态转换
- **你可以直接创建任务** — 随时使用 +创建任务 按钮
- **卡住的任务自动恢复** — 如果 Agent 崩溃，巡检哨兵会在超时后把任务释放回 Backlog（默认 2 小时）
- **多个 Agent 不能抢同一任务** — 系统保证每个任务只被一个 Agent 认领

### 5.3 优先级与严重程度

| 字段 | 含义 | 取值 |
|------|------|------|
| **优先级** | 对业务有多紧急 | Urgent → High → Medium → Low |
| **严重程度** | 问题有多严重（Bug） | Critical → Major → Minor → Trivial |

Agent 优先认领高优先级任务。需要立即关注的任务设为 **Urgent**。

## 6. 设置与配置

所有设置位于 **WebUI → 设置**。修改即时生效 — 无需重启。

### 6.1 任务存储

| 后端 | 最适合 | 需要 |
|------|--------|------|
| **内置**（默认） | 快速上手、单机使用 | 无需配置 — 开箱即用 |
| **GitHub Projects** | 已使用 GitHub 的团队、公开可见性 | GitHub 账户 + 项目看板设置 |

随时切换后端。切换到 GitHub 时，内置存储中的任务会保留，反之亦然。

### 6.2 AI 模型配置

为工作实例配置 AI 模型访问：

| 设置 | 描述 |
|------|------|
| **API Key** | AI 模型 API 密钥（安全存储，UI 中脱敏显示） |
| **Base URL** | AI 模型 API 端点 |
| **默认模型** | 新实例的默认模型 |

工作实例从控制中心接收模型凭据 — 不在本地存储。

### 6.3 调度参数

| 设置 | 默认值 | 作用 |
|------|--------|------|
| **锁过期时间** | 2 小时 | Agent 持有任务的最长时间，超时自动释放 |
| **巡检间隔** | 60 秒 | 系统检查卡住/过期任务的频率 |
| **心跳超时** | 120 秒 | 无心跳后将 Agent 标记为离线的时间 |
| **拉取间隔** | 30 秒 | Agent 检查新任务的频率（不使用 Push 时） |

默认值适用于大多数情况。如果 Agent 处理非常长或非常短的任务，可调整锁过期时间。

## 7. 故障排除

### "看板上没有任务"

- 你创建了吗？点击 **+ 创建任务** 添加一个。
- 如果使用 GitHub Projects：检查连接设置是否正确（设置页面）。
- 尝试刷新页面。

### "Agent 无法认领任务"

- 检查**实例管理** — Agent 是否已批准并在线上？
- 任务是否设置了 Agent 角色？如果设置了，只有该角色的 Agent 才能认领。清除角色字段让任意 Agent 认领。

### "任务卡在 Claimed 状态"

- 认领该任务的 Agent 可能意外停止了。
- 巡检哨兵会在锁过期时间后自动释放（默认 2 小时）。
- 如果需要更快释放，请你的团队重启控制中心。

### "Agent 显示 OFFLINE 但应该在工作"

- Agent 的心跳可能超时了（默认 120 秒无联系）。
- Agent 会自动重连并回到 ONLINE 状态。
- 如果一直 OFFLINE，请你的团队检查 Agent 的机器和日志。

### "无法登录"

- 默认凭据：用户名 `admin`，密码 `cexia123`。首次使用请用这些。
- 如果已修改密码但忘记了，请你的团队重置。
- 检查是否使用了正确的 URL。

### "其他问题"

所有系统活动都在**审计日志**中 — 从那里开始查看发生了什么。如需更深入调查，你的团队可以检查服务器上的系统日志。
